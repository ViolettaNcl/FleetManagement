# Анализ рисков

## Технические риски
- **Сбой базы данных**: Потеря доступа к SQL Server может нарушить работу приложения.
  - *Меры*: Регулярные резервные копии ([скрипт базы данных](./FleetManagment/Документы/script.sql)), настройка транзакций.
- **Ошибки авторизации**: Неправильная работа ролей (`admin@admin`, `user@user`) может ограничить доступ.
  - *Меры*: Тестировать `AuthenticationService` с MSTest, ограничить попытки входа.
- **Ошибки в управлении данными**: Проблемы с CRUD для маршрутов, водителей, транспорта.
  - *Меры*: Использовать MSTest для `DriverService`, `RouteService`, `VehicleService` с изолированными списками.
- **Уязвимости безопасности**: Возможность SQL-инъекций или утечки данных из `App.config`.
  - *Меры*: Параметризованные запросы, шифрование строки подключения.

## Человеческие риски
- **Недостаток обучения**: Пользователи могут не освоить систему.
  - *Меры*: Подготовить [документацию](./FleetManagment/Документы/ДокументацияПользователей.md), провести тренинги.
- **Ошибки конфигурации**: Неправильная настройка SQL Server или `App.config`.
  - *Меры*: Добавить [инструкцию](./FleetManagment/Документы/Инструкция.md).

## SWOT-анализ
- **S (Сильные стороны)**:
  - Простая WPF-архитектура с MVVM, легко поддерживается.
  - MSTest для тестирования сервисов (`AuthenticationService`, `DriverService` и др.).
  - Автоматизация сборки, тестов и документации через PowerShell-скрипт `build.ps1`.
  - Подробная документация для пользователей и разработчиков.
- **W (Слабые стороны)**:
  - Низкое покрытие кода тестами (4%).
  - Отсутствие CI/CD и логирования ошибок.
  - Зависимость от SQL Server.
  - Отсутствие оптимизации для больших данных.
- **O (Возможности)**:
  - Внедрение GitHub Actions с PowerShell-скриптами (`build.ps1`) для CI/CD, автоматизирующих сборку, тестирование и документацию.
  - Интеграция с API карт для маршрутов.
  - Миграция на .NET Core для кроссплатформенности.
  - Автоматизация тестирования базы с EF Core InMemory.
- **T (Угрозы)**:
  - Сбои SQL Server из-за ошибок конфигурации.
  - Человеческий фактор в использовании и разработке.
  - Уязвимости безопасности (SQL-инъекции).
