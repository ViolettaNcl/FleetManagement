# Анализ рисков

## Технические риски
- **Сбой базы данных**: Потеря доступа к SQL Server может нарушить работу приложения.
  - *Меры*: [Открыть скрипт базы данных](/script.sql), сделать резервные копии.
- **Ошибки авторизации**: Неправильная работа ролей (`admin@admin`, `user@user`) может ограничить доступ.
  - *Меры*: Тестировать с MSTest для `AuthenticationService`.
- **Ошибки в управлении данными**: Проблемы с CRUD для маршрутов, водителей, транспорта.
  - *Меры*: Использовать MSTest для `DriverService`, `RouteService`, `VehicleService` с изолированными списками.

## Человеческие риски
- **Недостаток обучения**: Пользователи могут не освоить систему.
  - *Меры*: Подготовить инструкции, провести тренинги.

## SWOT-анализ
- **S (Сильные стороны)**: Простая WPF-архитектура, MSTest для тестирования.
- **W (Слабые стороны)**: Ограниченное тестирование базы, нет CI/CD.
- **O (Возможности)**: Автоматизация через GitHub Actions
- **T (Угрозы)**: Сбои SQL Server, человеческий фактор.
