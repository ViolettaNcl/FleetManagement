# Integrated batch dispatch

The operational browser planner accepts up to 40 fixed-time, user-entered trip requests (origin, destination, departure, arrival and distance). It compares earliest-start and shortest-duration ordering using existing availability recommendations, excluding vehicles due at departure, reservation overlaps and busy resources, and honoring optional strict driver shifts. Newly proposed trips are staged in a copy so they also consume availability. The recommendation maximizes assigned requests among the two heuristic candidates, with earliest-start as tie-break; no global optimality claim.

Preview does not mutate the register. Explicit confirmation applies only the assigned subset, after revalidating every proposal against current clock, service status, shifts, reservations and existing/newly staged trips. Any failure aborts the entire subset before mutation. New IDs are allocated from current register. The browser persists applied trips via existing snapshot, with the existing session-only fallback if storage fails. Unassigned requests stay in the component session; navigation loses pending requests. No server transaction, idempotency across tabs, actual road routing, vehicle capacity data, cumulative future mileage prediction or driving-rest compliance. The synthetic multi-stop VRP lab stays independent: its coordinates and capacities are not fabricated as registered trips.
